# md2gdoc

Конвертирует один или несколько Markdown-файлов (или папку) в **один** Google Doc.

```bash
md2gdoc README.md                          # один файл → один документ
md2gdoc intro.md api.md faq.md -t "Гайд"   # несколько файлов, порядок как в аргументах
md2gdoc ./docs --file-titles               # папка (рекурсивно, натуральная сортировка)
md2gdoc ./docs --update 1AbC...xyz         # перезаписать существующий документ
md2gdoc ./docs --dry-run --html-out out.html   # без загрузки, посмотреть HTML
```

## Как это работает

Markdown рендерится в HTML (markdown-it-py), HTML загружается в Drive с
`mimeType = application/vnd.google-apps.document` — Google сам конвертирует его
в нативный документ. Docs API (`batchUpdate`) не используется: он требует ручного
расчёта индексов и очень сложен для таблиц/списков.

## Установка

```bash
pip install -e .
```

## Настройка доступа к Google (один раз)

1. https://console.cloud.google.com → создать проект.
2. *APIs & Services → Library* → включить **Google Drive API**.
3. *OAuth consent screen* → тип **External**, добавить себя в **Test users**.
4. *Credentials → Create credentials → OAuth client ID* → тип **Desktop app** → скачать JSON.
5. Положить файл в `~/.config/md2gdoc/credentials.json` (или передавать `--credentials путь`).

При первом запуске откроется браузер для входа; токен сохранится в
`~/.config/md2gdoc/token-<scope>.json`.

## Опции

| Опция | Что делает |
|---|---|
| `-t, --title` | Название документа. По умолчанию: имя папки / title из front matter / первый `# H1` / имя файла |
| `--separator pagebreak\|hr\|none` | Что вставлять между файлами (по умолчанию разрыв страницы) |
| `--file-titles` | Перед каждым файлом H1 с его названием, собственные заголовки файла сдвигаются на уровень вниз |
| `--no-recursive` | Не заходить в подпапки |
| `--update DOC_ID` | Перезаписать существующий документ (ссылка сохраняется) |
| `--folder-id ID` | Создать в папке Drive (обычно нужен `--scope full`) |
| `--scope file\|full` | `file` — доступ только к своим файлам (по умолчанию), `full` — весь Drive |
| `--html-out`, `--dry-run` | Сохранить HTML / не загружать |
| `--no-browser`, `--open` | Авторизация без автозапуска браузера / открыть результат |

## Что поддерживается

Заголовки, списки, таблицы (с выравниванием), код с подсветкой (Pygments, inline-стили),
inline-код, цитаты, ссылки, сноски, чек-листы, зачёркивание, YAML front matter (вырезается),
локальные картинки (встраиваются как base64), картинки по URL.

При склейке: ссылки вида `[текст](other.md)` на файлы из того же набора
превращаются во внутренние якоря, id сносок не конфликтуют между файлами.

## Ограничения и известные проблемы

- **Картинки по URL** Google скачивает сам — работает только для публично доступных адресов.
- **SVG** Google Docs не поддерживает — такие картинки пропускаются с предупреждением.
- **Mermaid / PlantUML / формулы LaTeX** не рендерятся — остаются как код/текст.
- **Ссылки на .md-файлы** вне набора (или в режиме одного файла) будут битыми — выводится предупреждение.
- **Лимит Google Docs** ~1,02 млн символов на документ — большие папки надо дробить.
- **Перезапуск без `--update`** каждый раз создаёт новый документ (дубликаты).
- `--update` перезаписывает документ целиком: комментарии и правки, сделанные в Docs, пропадут.
- **`--scope file`** не даёт класть документ в папку, созданную вручную, и обновлять чужие документы — нужен `--scope full`.
- OAuth-приложение в режиме **Testing** выдаёт refresh-токен на 7 дней — потом снова логин в браузере.
- На **удалённом сервере без браузера** локальный OAuth-redirect не сработает: авторизуйтесь
  локально и скопируйте `token-*.json`, или пробросьте порт по SSH.
- Сервисный аккаунт не подходит для «Моего диска» (у него нет квоты) — только Shared Drive.
- Сопоставление HTML → Docs делает Google, точный вид (отступы, фон кода) может отличаться.
